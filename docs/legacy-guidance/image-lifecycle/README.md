# Image Editor optional lifecycle research

Based on 1656cd0db; no deployment. Image Editor reports revision, dirty state and outstanding opens, save, file/folder pickers, annotation/watermark loads and inspection. Quiescence makes its window inert, prevents new app actions and is reversible; an editor modification still increments revision. The desktop uses the optional contract for this app while retaining its previous fallback if absent. React unmount and the lifecycle close are idempotent.

Run `node --test tests/image-lifecycle-reference.test.mjs`. Build an isolated image-editor-only catalog and run `tests/jsketcher-preview-csp.py --isolated` against it; run `tests/image-lifecycle-session-review.test.mjs` with CODI_TEST_URL and CODI_TEST_CDP set to that loopback preview and a dedicated Chromium debugging endpoint. The browser test changes an actual Filerobot resize control during confirmation, blocks a real annotation picker and a file write, verifies the saved 24×24 PNG through the signed server gateway, tests failure/release and account switch. The existing annotation My files browser test separately verified saved pixels. These were desktop Chromium tests, not physical mobile tests. The confirmation-race test dispatches DOM input events against the real Filerobot control, rather than physical input through a modal. Multiple simultaneously open image windows, arbitrary add-on callbacks and interrupted server sync after a completed local save are not qualified here. This is research; apps without an audited lifecycle still use the existing conservative session behavior.
